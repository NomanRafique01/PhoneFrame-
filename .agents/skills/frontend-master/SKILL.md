# Frontend Master — Orchestrator

**ANNOUNCE:** "Reading `frontend-master` to route this task with Taste, Anti-SOP, and Dynamic Responsive baselines."

**Core Rule:** Every UI component must fit all screen sizes dynamically — from 320px phones to 2560px ultra-wide desktops. Never build without consulting `.agents/brain/decisions/frontend.md`.

---

## 1. The Three Mandatory Frontend Baselines

Every single frontend build, component edit, or page design automatically binds to these three pillars:

### Pillar 1: Award-Grade Art Direction (Taste Kill v2)
- `design-taste-frontend` + `ui-taste-enforcer`: Grounded subject inventory (8–12 client traits), researched composition blueprints, zero stock template defaults.

### Pillar 2: Anti-AI SOP Quality Filter
- `ui-tells-eliminator`: Kills pill badges, tracked uppercase eyebrows, 3-card centered icon grids, and AI color cliches (cream/terracotta, neon-on-black).
- `anti-slop-enforcer`: Purges synthetic marketing copy and conversational filler.

### Pillar 3: Universal Dynamic Sizing & Responsiveness (Mandatory)
- `phone-layout-master`: Mobile phone perfection (320px–480px, `100svh`, 44×44px touch targets, safe-area insets, bottom sheets, zero horizontal scroll).
- `desktop-ui-architect`: Desktop workstation density (768px–2560px, multi-pane spatial hierarchy, container queries `@container`, `max-w-7xl` content bounds).
- `dynamic-ui-engine`: Fluid CSS clamp math, aspect-ratio stability, zero cumulative layout shift.

---

## 2. Dedicated UI Planning ($plan-frontend)

When the user invokes `$plan-frontend` or requests a UI plan:
1. Activate `frontend-planner`.
2. Produce the complete UI Blueprint: Subject inventory, fluid token matrix, phone layout, desktop layout, and Anti-Slop verification.
3. Present the plan to the user and ask for confirmation before writing code.
